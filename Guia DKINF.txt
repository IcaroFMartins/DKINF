 Leitura e Renderização do Mapa
O objetivo desta fase é fazer com que o programa abra um arquivo .txt, interprete os caracteres internos e os transforme em elementos visuais na janela da Raylib.

1. Função de Carregamento (carregarMapa)
Criar uma função, por exemplo void carregarMapa(int fase), que automatize a entrada de dados.
    • Abertura do Arquivo: Use fopen para abrir o arquivo correspondente à fase atual (ex: mapa1.txt).
    • Variáveis Locais de Suporte: * FILE *arq: Ponteiro para manipular os arquivos.
        ◦ int i, j: Contadores para percorrer a matriz.
    • Varredura com Laços Gêmeos: Utilize dois laços for aninhados (30 linhas por 30 colunas) para preencher a matriz mapa[i][j].
    • Captura de Dados: Use fscanf(arq, " %c", &mapa[i][j]);.
        ◦ O espaço antes do %c faz o C ignorar automaticamente os espaços e as quebras de linha (\n), evitando que o mapa fique "torto" ou deslocado na memória.



2. Processamento de Entidades Dinâmicas
Durante a leitura do arquivo (dentro dos mesmos laços for), o código deve identificar e extrair os objetos que se movem, impedindo que eles fiquem "pintados" no fundo do cenário:
    • Jogador ('P'):
        ◦ Salvar as coordenadas: player.pos.linha = i; e player.pos.coluna = j;.
        ◦ Limpeza: Substituir mapa[i][j] por um espaço vazio ' ' (ou 'Z') para que o caractere não seja desenhado como parte do cenário estático.
    • Inimigos ('E'):
        ◦ Armazenar no vetor: listaInimigos[qtdInimigos].pos.linha = i; e listaInimigos[qtdInimigos].pos.coluna = j;.
        ◦ Definir a direção inicial: listaInimigos[qtdInimigos].direcao = 1; (Direita).
        ◦ Incrementar o contador: qtdInimigos++;.
        ◦ Também substituir o caractere na matriz por um espaço vazio ' '.


3. O Loop de Desenho (Renderização)
No  main, dentro do loop while(!WindowShouldClose()) e entre as funções BeginDrawing() e EndDrawing(), implementar a lógica visual:
    • Renderização do Cenário: Percorra a matriz mapa com dois for e desenhe conforme o caractere:
        ◦ 'Z' (Chão): Desenhe um retângulo azul.
        ◦ 'S' / 'D' / 'H' (Escadas): Desenhe o elemento (ex: retângulo marrom).
        ◦ 'F' (Porta/Vitória): Desenhe a porta (ex: retângulo amarelo). Atenção: Não remova o 'F' da matriz, pois ele é necessário para detectar a vitória depois.
    • Cálculo de Pixels: Use sempre a fórmula de conversão:
        ◦ X_Tela = coluna * TILE_SIZE
        ◦ Y_Tela = linha * TILE_SIZE
        ◦ Exemplo: DrawRectangle(j * TILE_SIZE, i * TILE_SIZE, TILE_SIZE, TILE_SIZE, COR);



4. Desenhando as Entidades (Camada Superior)
Após desenhar todo o cenário estático, desenhar o jogador e os inimigos usando as posições salvas nas structs. Isso garante que eles apareçam "na frente" do cenário:

 Movimentação e Lógica do Jogador
O objetivo é permitir que o utilizador controle o quadrado vermelho (player) usando o teclado, respeitando as limitações do mapa (não atravessar o chão e usar escadas).
1. Captura de Entrada (Teclado)
Dentro do loop principal, antes de desenhar, verificar qual tecla foi pressionada usando as funções da Raylib:
    • Subir: IsKeyPressed(KEY_W) || IsKeyPressed(KEY_UP)
    • Descer: IsKeyPressed(KEY_S) || IsKeyPressed(KEY_DOWN)
    • Esquerda: IsKeyPressed(KEY_A) || IsKeyPressed(KEY_LEFT)
    • Direita: IsKeyPressed(KEY_D) || IsKeyPressed(KEY_RIGHT)
Por que usar IsKeyPressed e não IsKeyDown?
No nível básico do trabalho (movimentação por matriz), é melhor usar IsKeyPressed:
    • Ele detecta apenas um toque. Isso faz o jogador se mover "quadradinho por quadradinho".
    • Se usar IsKeyDown (detecta tecla segurada), o jogador vai atravessar a matriz inteira em um segundo, pois o jogo roda a 60 frames por segundo.



2. Movimentação Horizontal e Gravidade Simples
O movimento depende do que está abaixo do jogador: O jogador só pode se mover para os lados se a posição abaixo dele (mapa[linha + 1][coluna]) for chão ('Z') ou parte de uma escada ('H', 'S', 'D').
Lógica: * Se apertar 'D', verificar se a coluna à direita está dentro dos limites (30) e se há chão abaixo.
        ◦ Se não houver chão abaixo, o jogador deve "cair" (aumentar a linha) até encontrar um 'Z'.

3. Lógica das Escadas
Conforme o enunciado para o nível básico, a movimentação vertical é simplificada:
    • Subida: Se o jogador estiver sobre um caractere 'S' (Início de Subida) e pressionar W, a posição dele deve ser atualizada para a coordenada do 'H' ou 'D' correspondente acima.
    • Descida: Se o jogador estiver sobre um caractere 'D' (Início de Descida) e pressionar S, ele é movido para o caractere 'H' ou 'S' correspondente abaixo.

4. Mudança de Fase (Colisão com a Porta)
A cada movimento, o código deve checar o conteúdo da matriz na posição atual do jogador:
    • Verificação: if (mapa[player.pos.linha][player.pos.coluna] == 'F').
    • Ação: 
1. Incrementar faseAtual. 
2. Chamar novamente a função carregarMapa(faseAtual). 
3. Resetar o tempo ou a posição do jogador.

Pontos técnicos para orientar o código:
Variáveis Temporárias de Teste:
int proxLinha, proxColuna: Usa estas variáveis para calcular o movimento antes de o aplicar à struct player. Só atualiza a posição real se o movimento for válido.
Sistema de Bloqueio de Bordas:
Garante que o jogador não saia da matriz: if (proxColuna >= 0 && proxColuna < 30).
Fluxo de Execução:
1º: Ler Teclado -> 2º: Validar contra a Matriz -> 3º: Aplicar Gravidade (se necessário) -> 4º: Verificar Vitória.

Inimigos e Colisão
O objetivo desta fase é fazer com que os inimigos se movam sozinhos pela matriz e detectem se encostaram no jogador, o que causa a derrota.
1. Movimentação Automática dos Inimigos
Diferente do jogador, o inimigo não espera um comando de teclado. Ele se move a cada X frames ou segundos.
    • Lógica de Patrulha: * O inimigo tenta mover-se na sua direcao atual (1 para direita, -1 para esquerda).
        ◦ Se a próxima célula for uma parede (fora da matriz) ou se não houver chão ('Z') abaixo da próxima posição, ele inverte a direcao (direcao *= -1).
    • Velocidade: Para que o jogo seja justo, use um contador de frames para mover o inimigo apenas uma vez a cada 10 ou 15 frames (já que o jogo roda a 60 FPS).
2. O Loop dos Inimigos
Como tem vários inimigos, deve usar um laço for para atualizar todos eles:
C
for (int i = 0; i < qtdInimigos; i++) {
    // 1. Calcular próxima posição
    // 2. Verificar se deve inverter a direção
    // 3. Atualizar posição real na struct listaInimigos[i]
}

3. Detecção de Colisão (Derrota)
Após mover o jogador e mover os inimigos, verificar se eles ocupam o mesmo espaço na matriz.
    • A verificação: Comparar se player.pos.linha == listaInimigos[i].pos.linha E player.pos.coluna == listaInimigos[i].pos.coluna.
    • Consequência: Se a condição for verdadeira:
        1. Mudar estadoJogo para GAME_OVER.
        2. Parar o cronômetro de tempo.
4. Renderização dos Inimigos
Lembrar de adicionar o desenho deles no loop de renderização (Fase 2):
    • Usar uma cor diferente (ex: PURPLE ou ORANGE) para distinguir do jogador.
    • DrawRectangle(listaInimigos[i].pos.coluna * TILE_SIZE, listaInimigos[i].pos.linha * TILE_SIZE, TILE_SIZE, TILE_SIZE, PURPLE);


    1. Contador de Frames para Movimento:
        ◦ Variável int framesCounterInimigo para controlar o "passo" do inimigo.
    2. IA de Plataforma:
        ◦ O inimigo deve checar duas coisas antes de andar:
            1. Se a frente é um espaço vazio (evita que ele caia da plataforma).
            2. Se a frente é o limite da matriz (0 ou 29).
    3. Reset de Inimigos:
        ◦ Sempre que carregarMapa for chamada, lembre-se de zerar qtdInimigos = 0 antes de ler o arquivo, para não acumular inimigos da fase anterior no vetor.

Polimento e Mecânicas Avançadas

Para o pulo não ser apenas um "teletransporte", precisamos de uma lógica de estado:

    • Ação: Quando KEY_SPACE for pressionada e o jogador estiver no chão:
        ◦ estaPulando = true.
        ◦ O jogador sobe algumas linhas na matriz (ou pixels, se estiver usando coordenadas suaves).
        ◦ Após atingir a altura máxima, a gravidade (Fase 3) puxa-o de volta.
    • Dica AlgProg: Se o pulo for apenas na matriz, ele pode "saltar" 2 linhas acima e, após 10 frames, a gravidade faz o resto.
2. Sistema de Vidas e Reset
O enunciado sugere que o jogador não deve ser punido com o fim do jogo imediato ao tocar num inimigo.
    • Vidas Iniciais: Comece com int vidas = 3.
    • Mecânica de Dano:
        ◦ Se colisaoInimigo == true:
            ▪ vidas--.
            ▪ Se vidas > 0: Reseta a posição do jogador para o inicioFase (não fecha o jogo).
            ▪ Se vidas == 0: estadoJogo = GAME_OVER.
3. Itens e Vidas Extras
Para ganhar nota máxima nos "Desejáveis" (Extras):
    • O Caractere 'V': Adicionar no seu .txt o caractere 'V'.

        2. mapa[i][j] = ' ' (o item desaparece da matriz).
        3. Toca um som de "Power Up".
